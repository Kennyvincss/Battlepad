# BATTLE — 1v1 Token Battle Launchpad (prototype)

Two tokens fight a 1v1 battle while people **trade the real tokens** around it. It is not a prediction market: you buy and sell tokens through an AMM, and the battle is a competitive layer on top of those markets.

> **All data in this prototype is simulated in the browser.** Markets, wallets, trades, holders and randomness-beacon values are generated by `src/sim/engine.ts`, and every simulated value is labelled in the UI.

## Run

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # typecheck + production build into dist/
```

Use the **Sim speed** control (1× / 10× / 60×) in the top ribbon to watch a battle pass its 1-hour minimum and hit its random end.

## Core mechanics

| Mechanic | Where |
|---|---|
| Random battle end: 1h minimum, no countdown, verifiable checks | `src/lib/randomEnd.ts`, `src/lib/rules.ts` |
| Battle Score: 60% time-weighted performance, 20% holder growth, 20% market quality | `src/lib/score.ts` |
| AMM quoting and settlement (the same code path for both) | `src/lib/amm.ts` |
| Integrity monitoring (wash, circular, clusters, sync), with legitimate surges *not* flagged | `SimEngine.maybeIntegrityEvents` |
| Battle Loyalty rewards (amount × time held × HoldFactor) | `SimEngine.loyaltyFor`, `score.ts#holdFactor` |

### Verifiable random end
1. Before start, `rulesHash = sha256(canonical(rules, tokenA, tokenB))` is published with the battle id.
2. After the minimum, every epoch `k` uses the first public beacon round (drand in production) published **after** the epoch closes.
3. `value_k = sha256(battleId | rulesHash | randomness_k)` → [0,1). The battle ends when `value_k < hazardPerEpoch`.
4. Every check is logged on the battle page, and **Re-verify all checks** recomputes them.

## Tournaments, treasury, spectating, chat, result cards

| Feature | Where |
|---|---|
| Tournaments (4/8-token brackets; every match is an ordinary battle with `tournamentId`) | `SimEngine.createTournament / advanceTournament`, `src/pages/TournamentsPage.tsx` |
| Battle Treasury: funded at lock + 30% of the 1% swap fee while live, paid out by the locked split | `SimEngine.distributeTreasury`, `src/components/Treasury.tsx`, `src/pages/TreasuryPage.tsx` |
| Spectator mode (`/battle/:id/watch`): scoreboard, play-by-play, notable trades, watchers | `src/pages/SpectatorPage.tsx` |
| Battle chat with mentions, emoji, report / mute / block / delete | `src/components/Chat.tsx`, `src/sim/chat.ts` |
| Shareable Battle Result Cards with variants: tournament, streak, photo finish, domination, rematch | `src/components/ShareCard.tsx`, `cardVariants` in `src/lib/view.ts` |

## Going live

The UI talks only to the `BattleDataProvider` interface (`src/data/provider.ts`) through `useData()`. To use real chain data, implement that interface on top of an indexer or websocket feed (prices, trades, holders, liquidity), a wallet adapter (balances, swaps), the battle program (commitments, end checks, reward claims) and a drand client. Then swap it in `src/data/DataContext.tsx`.
